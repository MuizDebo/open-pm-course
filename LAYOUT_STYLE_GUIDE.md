# Lesson layout and style guide

Every lesson and project is one Markdown file under `src/content/docs/`. The layout mirrors
The Odin Project's, so a learner who has used that site feels at home. The headings below are
required, in this order, unless a line says otherwise.

## Frontmatter

```yaml
---
title: "2.1.3 Saying no"          # number, space, title. The number is the lesson's id.
description: "One sentence."       # shown in search results and link previews
---
```

Do not set `sidebar` in frontmatter. The sidebar is generated from `CURRICULUM.md`.

## Lesson layout

```markdown
## Introduction
A short paragraph on what the lesson covers and why it matters. No more than three paragraphs.

## Lesson overview
This section contains a general overview of topics that you will learn in this lesson.
- Bullet per concept. Seven at most.

## (Your own headings)
The teaching. As many sections as the material needs. Use `###` for subsections.

## Assignment
<div class="assignment">

1. Numbered list of 3 to 5 things to read, watch or do. Each item says what it is for.
   - Nested bullets hold instructions for that item.

</div>

## Additional resources
- Optional. Supplemental links, each with a note on why it is worth the time. Delete the
  section if there are none.
```

## Project layout

```markdown
## Introduction
What the learner will produce and why it matters in real PM work.

## (Optional pre-assignment section)
Background a learner needs before starting. Delete if not needed.

## Assignment
<div class="assignment">

1. Numbered list of requirements. Concrete enough to tell when it is done.

#### Extra credit
- Optional stretch goals.

</div>

## Submitting your work
Post a link to your artifact in this project's GitHub Discussions thread. Review two others.
```

## Writing rules

- **Link, do not copy.** External articles, videos and podcasts are linked with a sentence on
  why to read them. Quote at most a short phrase. Source repos with a permissive licence may
  be excerpted with attribution; see `SOURCES.md` for which ones.
- **Every link gets a purpose.** "Read X" is not enough. "Read X for the argument that date
  roadmaps are promises, not plans" is.
- **Plain English.** Short sentences. Define jargon the first time. No "simply" or "just".
- **Second person.** "You will" not "the learner will". "We" is the course, not the author.
- **Honest.** If a framework is contested, say so. If something is hard, say so.
- **Videos and podcasts** are welcome in Assignments and Additional resources. Give the
  length so people can plan.
- **Headings** start at `##`. The page title is the `#`.
- **Asides** use Starlight syntax: `:::note`, `:::tip`, `:::caution`. Keep them rare.
- **No images without alt text.** Store images under `src/assets/` and import them.

## Draft marker

A lesson that is not yet written carries this block at the top of its Introduction. The
scaffold script reads it to show a "Draft" badge in the sidebar. Delete it when the lesson
is written.

```markdown
:::caution[Draft]
This lesson has not been written yet. ...
:::
```

## File naming

Generated by `npm run scaffold` from `CURRICULUM.md`. Do not rename files by hand. To rename a
lesson, change its title in the map, delete the old file, and re-run the scaffold.
