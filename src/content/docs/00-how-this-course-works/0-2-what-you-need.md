## Introduction

Product management needs very little equipment. You will write, draw, talk to people and
keep track of decisions. This lesson lists the tools the course assumes and gets them set
up before Course 1, so that nothing in a later project stalls on "I don't have a place to
put this".

Everything here is free. If a lesson later suggests a paid tool, it will say so and offer a
free alternative. You do not need to buy software to become a product manager.

## Lesson overview

This section contains a general overview of topics that you will learn in this lesson.

- The five things every learner needs: a GitHub account, a work repository, a writing tool,
  a whiteboard tool and a calendar block.
- Why your course work lives in one public repository.
- What is optional and what to ignore for now.

## A GitHub account

GitHub is where this course lives, where you submit projects, where you ask for help and
where you contribute fixes. It is also where a lot of product work happens in software
companies, so being comfortable there is a job skill, not just a course requirement.

If you do not have an account, make one with a name you would be happy to show a hiring
manager. If you have one from coding, use it. You do not need to know Git to take this
course. Everything can be done through the GitHub website.

## A work repository

Create one public repository called `pm-course-work` (or whatever you like). Every project
you produce goes in there, one folder per project, named by the project number:

```
pm-course-work/
  README.md
  1-1-5-role-audit/
  1-2-4-lifecycle-teardown/
  2-1-5-decision-journal/
  ...
```

A folder holds whatever the artifact is: a Markdown document, a PDF export, a PNG of a
whiteboard, a link to a Google Doc in a `README.md`. When you submit a project, you post the
link to its folder.

Why one public repository rather than a private drive:

- **It is your portfolio.** By the end of the course it holds twenty-nine artifacts in the
  order you made them. Course 8 turns it into something you can send to a recruiter.
- **It is reviewable.** Other learners can read it and comment. That is where most of the
  learning in this course happens.
- **It shows growth.** Your first audience map will be worse than your capstone one. That is
  the point.

If a specific project uses confidential material from your job, keep that one artifact
private and submit a sanitised version. Lesson 0.3 covers how.

## A writing tool

Most of what a PM produces is prose. Use whatever lets you write without friction and
export to something others can read:

- **Markdown files in your repository.** Simplest, versioned, no accounts. Fine for
  anything without heavy formatting.
- **Google Docs.** Best for anything other people will comment on. Share with "anyone with
  the link can comment" and put the link in the project folder's `README.md`.
- **Notion or Obsidian.** Good if you already use them. Export or share a public link when
  you submit.

Pick one and stop deciding. Switching tools is a well-known way to avoid writing.

## A whiteboard tool

Several projects ask you to draw: audience maps, system diagrams, product loops, metrics
trees. Hand-drawn on paper and photographed is completely acceptable. If you want a digital
tool, [Excalidraw](https://excalidraw.com/) is free, needs no account, and exports to PNG.
[FigJam](https://www.figma.com/figjam/) and [tldraw](https://www.tldraw.com/) also work.

You do not need to learn Figma for this course. Course 5 touches on design literacy, and
sketches are enough.

## A calendar block

Decide now when you will work on this course each week and put it in your calendar as a
recurring event. Two or three blocks of two to three hours is the pattern that gets people
through. If your week does not have eight hours in it, take fewer and expect the course to
take longer. That is fine. Vanishing for a month and feeling guilty is what to avoid.

## Optional, later

- **A spreadsheet.** Google Sheets or Excel. Course 4 uses one for prioritisation and Course
  6 for metrics. You almost certainly have one.
- **A place to keep a decision journal.** Course 2 starts one. A notes app or a Markdown
  file is enough.
- **An AI coding tool** such as Cursor, Claude or v0. Course 7 uses one to prototype. Do not
  set it up now.

## What to ignore

You do not need a roadmapping tool, a product analytics subscription, a Jira account, a
certification, or a laptop newer than the one you have. If a later lesson needs something
specific, it will say so at the top.

## Assignment

<div class="assignment">

1. If you do not have a GitHub account,
   [create one](https://docs.github.com/en/get-started/start-your-journey/creating-an-account-on-github).
   Add a profile photo and a one-line bio. Hiring managers do look.
2. Work through GitHub's
   [Hello World](https://docs.github.com/en/get-started/start-your-journey/hello-world)
   guide, twenty minutes. It walks you through creating a repository, making a change and
   opening a pull request, entirely in the browser. That is every GitHub skill this course
   needs.
3. Create your `pm-course-work` repository, public, with a `README.md` that has your name,
   the date you started, and a link back to this course. This is your first commit of the
   course.
4. Put your weekly course blocks in your calendar as recurring events. Then open
   [Excalidraw](https://excalidraw.com/), draw a box with "I started" in it, export it as
   PNG and commit it to your repository. Trivial on purpose: you have now used every tool
   the course needs.

</div>

## Additional resources

- [GitHub Skills](https://skills.github.com/). Free interactive courses on GitHub itself, if
  the Hello World guide left you wanting more. "Introduction to GitHub" is the one to take.
- [Markdown Guide](https://www.markdownguide.org/basic-syntax/). Ten minutes on the handful
  of symbols that turn plain text into headings, lists and links. Every lesson in this course
  is written in it.
